# ルビカメラ（RubyCam）

外国語で書かれた紙をカメラで撮ると、**その言語の読み方をふりがな（ルビ）で返す**Webアプリです。

写真の上にルビを重ねる表示と、読み取った文章にルビを振る表示の2つを持ちます。
語をタップするとその単語だけを読み上げます。

## 対応言語

| 言語 | ルビ | 読みの出しかた |
|---|---|---|
| 英語 | カタカナ | 頻出語辞書（約520語）＋綴りからの推定 |
| 中国語 | ピンイン / カタカナ | pinyin-pro で漢字→ピンイン、ピンイン→カタカナは自前 |
| 韓国語 | カタカナ / ローマ字 | ハングルを字母に分解し、連音化・鼻音化・濃音化などを適用 |
| ベトナム語 | カタカナ＋声調 | 音節を頭子音+韻に分解。北部/南部を切替。綴りの誤りを自動補正 |
| ビルマ語 | カタカナ / ローマ字 | 音節を頭子音+介子音+韻に分解。積み重ねをほどき、鼻音後の濁りも反映 |
| スペイン語 | カタカナ | 綴り規則 |
| フランス語 | カタカナ | 綴り規則（鼻母音・語末の黙字を明示的に処理） |
| ドイツ語 | カタカナ | 綴り規則（母音の長短・語末無声化・ch の分岐） |
| イタリア語 | カタカナ | 綴り規則 |
| ポルトガル語 | カタカナ | 綴り規則 |
| ロシア語 | カタカナ / ローマ字 | キリル文字の転写 |
| ギリシャ語 | カタカナ / ローマ字 | ギリシャ文字の転写 |

ラテン文字の言語は、読み取った文章から言語を推定して切り替えを提案します。
ハングル・漢字・キリル・ギリシャ・ミャンマー文字は文字種で判別できます。

## ルビをふる範囲を選ぶ

全文にふると、知りたい語が埋もれます。「ルビの範囲」を
**選んだ語だけ** にすると、押した語にだけルビがつきます。

- 写真の上でも、下の文章表示でも、語を押せば入切できます
- 写真の上は**なぞって囲む**と、範囲内の語をまとめて選べます
- 「すべて選ぶ」「選択を消す」でまとめて切り替えられます

選んでいない語は、写真の上では破線で示します（押せる目印です）。
「読みをコピー」も、選んだ語だけを書き出します。

## 動かす

```bash
npm start          # http://localhost:8080 で配信（完全版）
npm test           # 読みの生成を検証（22 テスト）
npm run build      # dist/rubycam.html（1ファイル版）を作り直す
npm run package    # dist/rubycam.zip（配布一式）を作る
```

カメラを使うには **https か localhost** である必要があります（ブラウザの制約）。
`file://` で開いた1ファイル版では、環境によってカメラが起動できないことがありますが、
**「写真を選ぶ」（スマホなら撮影も選べます）はどこでも動きます。**

## 人に渡す

公開URLから開いたときは、画面下の「このアプリを共有する」に4つの経路が出ます。

| ボタン | 動き |
|---|---|
| 共有する | 端末の共有メニューを開く（LINE・メール・AirDrop など）。対応端末のみ表示 |
| LINEで送る | LINE の共有画面を直接開く。PCでもスマホでも動く |
| リンクをコピー | URLをクリップボードへ |
| QRコード | 目の前の相手が読み取れば、その場で開ける |

QRコードは [qrcode-generator](https://github.com/kazuhikoarase/qrcode-generator)（MIT）を
`src/vendor/` に同梱して使っています。実行時にネットへ取りに行きません。
画像ではなくSVGで描いているので、拡大しても印刷しても崩れません。

受け取った人が初めて開いたときは、「ホーム画面に追加」を一度だけ案内します
（閉じると次からは出ません）。ホーム画面から開けば、次からは1タップです。

LINE に貼ったときのプレビュー（タイトル・説明・画像）は OGP で指定しています。
プレビュー画像は `assets/og.png`、参照先のURLは公開時に
GitHub Actions が実際のURLへ書き換えます（`__SITE_URL__` を置換）。

保存したファイル版を開いているときは、リンクとして送れないため
共有の操作は出さず、その理由を表示します。

## スマートフォンで引っかかる点

実機で問題になったところと、その扱いです。

| 事象 | 原因 | 対処 |
|---|---|---|
| 「カメラで撮る」がアルバムと同じ動きになる | カメラの入口が2つあり、`capture` 属性頼みのほうを「カメラで撮る」にしていた。`capture` はPCでは常に無視され、スマホでも端末次第で選択画面になる | 入口を1つに統合。画面内カメラ（`getUserMedia`）が使えるならそれを使い、使えないときだけ端末の標準カメラに回す |
| 「カメラで撮る」が反応しない | ファイル入力を `display:none` で隠していた。iOS Safari はこの状態の入力を開けない | 隠し方を `opacity`/`clip-path` に変更し、`display` は保つ（`.file-input`） |
| LINE から開くとカメラが使えない | LINE のアプリ内ブラウザがカメラを通さないことがある | アプリ内ブラウザを見分けて警告し、「ブラウザで開く」を出す。共有するURLには `?openExternalBrowser=1` を付け、最初から端末のブラウザで開かせる |
| 直した不具合が届かない | Service Worker がキャッシュを先に返していた | 「まずネット、駄目ならキャッシュ」に変更（`sw.js`） |

`?openExternalBrowser=1` は LINE が用意している印で、
これが付いたリンクはアプリ内ブラウザではなく端末のブラウザで開かれます。

### 「カメラで撮る」の動き

押したときに何が起きるかは、開いている環境で決まります。
ボタンは1つで、利用者が使い分ける必要はありません。

| 環境 | 動き |
|---|---|
| https で開いていて、カメラを許可 | 画面内にカメラ映像が出る。ボタンが「撮影する」に変わる |
| カメラを断られた・使えなかった | 「端末のカメラで撮る」を案内する（押せば標準カメラが開く） |
| ファイルとして開いた・アプリ内ブラウザ | 押した時点で端末の標準カメラを開く |

端末カメラを開く呼び出しは、押した流れの中で同期的に行っています。
iOS は非同期の待ちを挟むと、この呼び出しを無視するためです。

## 仕組み

```
写真 ─→ 局所しきい値で白黒に整える（影・光のむらを消す）
          │
          ├─→ Tesseract.js（文字認識・単語ごとの座標つき）
          │
          ├─→ 言語判定（文字種 + 綴りの癖 + 機能語）
          │
          ├─→ 綴りの補正（ベトナム語のみ）
          │
          └─→ 読みの生成
                綴り ──[言語ごとの規則]──→ 音素表記 ──[共通表]──→ カタカナ
```

### 写真を整える

紙をカメラで撮ると、影や光のむらで濃さが場所ごとに変わります。
画像全体で1つのしきい値を決めると、影の側の文字が潰れるか、
明るい側の地色が黒く残ります。そこで**その画素の周りの平均と比べる
局所しきい値**にしています（`src/enhance.js`）。
積分画像を使うので、窓の大きさに関係なく1画素あたり一定の計算量です。

白抜き文字の看板などで白黒が反転した場合は、暗い画素が過半かどうかで
判定して戻します。設定の「文字を読みやすく補正する」で切れます。

### ビルマ語（ミャンマー文字）

ミャンマー文字は1音節が「子音字 + 介子音 + 母音記号 + 末子音」でできています。
読み取りを難しくするのは次の2点で、どちらも表と前処理で解いています。

1. **末子音は直前の母音と組んで1つの韻になる** — `ိ` + `တ်` は「イ」+「ト」ではなく
   「エイッ」。字面の足し算にならないので、韻の一覧表（`RHYMES`）で引きます
2. **積み重ね（`္`）は音節をまたぐ** — 「C1 ္ C2」は C1 が前の音節の末子音、
   C2 が次の音節の頭子音。先に `C1 ် C2` へほどいてから音節に切ります
   （`unstack`）。キンズィ `င်္` も同じ理屈です

あわせて、ミャンマー語らしさに効く2つを入れています。

- `ကျ` `ဂျ` のように軟口蓋音に介子音 `ျ`/`ြ` が付くと破擦音になる（チ / ジ）
- 前の音節が鼻音で終わると、続く無声音が濁る（`ရန်ကုန်` → ヤンゴウン）

文字が密なので、**認識にかける画像の長辺を 2200px** に上げています
（他の言語は 1600px）。細部が潰れると母音記号を取り違えるためです。

### ベトナム語

ベトナム語の音節は「頭子音 + 韻」に必ず分かれ、**取りうる韻は限られています**。
そこで韻の一覧表（`src/lang/vi.js` の `RHYMES`、約160種）を1つ持ち、
2つの用途に使っています。

1. **読みの生成** — 韻から音素へ引く。`anh`→アイン、`ach`→アック のような
   母音のずれや、`ơ`/`ư` が長母音であること（`phở`→フォー）を表に持たせている
2. **綴りの検査と補正** — 表に無い綴りは、ベトナム語として成り立たない音節。
   文字認識が記号を落としたと見て、記号を付け替えて直せるか試す

補正は**直し方が一意に決まるときだけ**行います。候補が複数あるときや、
記号が1つも読めていない語（元からそうなのか読み落としか区別できない）は
そのままにします。直した語は点線の下線で示し、元の綴りも見られます。

発音は**北部（ハノイ）が既定**で、南部（ホーチミン）も選べます。
`d` `gi` `r` `s` `v` は南北で最も大きく違うため、ここを切り替えています
（例: `dài` は北部でザイ、南部でヤイ）。声調はルビの末尾に記号で添え、
凡例を画面に出します。

読みの生成は**音素表記を挟む2段構え**にしています。
カタカナの当て方を `src/kana.js` の1箇所に集約することで、
言語をまたいで表記が揺れないようにするためです。

```
src/
  kana.js          音素 → カタカナ（全言語で共通）
  ocr.js           Tesseract.js の読み込みと単語・行の取り出し
  app.js           撮影・表示・読み上げ
  lang/
    rules.js       綴り → 音素 のルールエンジン
    index.js       言語一覧・言語判定・ルビを振る単位への切り分け
    en.js / en-dict.js / zh.js / ko.js / vi.js / ru.js / el.js / de.js / fr.js / romance.js
```

## 通信するもの／しないもの

- **写真は端末から出ません。** 文字認識も読みの生成もブラウザ内で完結します。
- 初回だけ、文字認識エンジン（Tesseract.js）と言語データ、
  中国語のピンイン辞書（pinyin-pro）をCDNから取得します。以降はブラウザに残ります。
- CDNは jsDelivr → unpkg の順に試します。

## 精度について

読みは**発音の目安**です。特に次は原理的に外れます。

- **英語の未知語** — 綴りから推定します。UIでは薄い色のルビで区別しています。
- **強勢（アクセント）の位置** — スペイン語・イタリア語などの長音は再現しきれていません。
- **中国語の声調** — ピンイン表示なら記号で分かりますが、カタカナには乗りません。
- **ビルマ語の声調** — 3声を区別していません。また文字認識そのものが
  ラテン文字ほど安定しません（字形が密で、結合が多いため）。
- **文字認識そのもの** — 手書き、傾き、暗い写真では読み違えます。
